# AquaShield backend API

The API is implemented by `main.py` with interactive OpenAPI documentation at
`/docs` and the OpenAPI JSON document at `/openapi.json`.

## Status and data policy

| Status | Meaning |
| --- | --- |
| `model_output` | A non-demo product contains a salinity value with recognized conductivity units, a model version, and a data year. |
| `observed` | Reserved for validated direct observations. No observed-data contract is available yet. |
| `demo` | Synthetic integration data only. It must not be presented as an observed value or model prediction. |
| `data_pending` | A required dataset, validated product, or production model output is not available. Numeric prediction fields are `null`. |
| `unavailable` | A map layer is not currently served. |
| `explanation_unavailable` | A validated prediction exists but a compatible explanation artifact is not available. |

At present, the repository does not contain
`data/processed/master_observations.parquet` or a production model artifact.
Consequently, prediction endpoints return `data_pending`. Synthetic artifacts
under `data/demo/` remain opt-in through `AQUASHIELD_PRODUCT_DIR`; API responses
identify these as `demo`, and the synthetic salinity index is not converted to
electrical conductivity or returned as a prediction.

The Parquet-to-feature-to-production-model execution path cannot be completed
without the real dataset schema and the trained model/feature contract. Until
those artifacts and contracts are supplied, the API does not infer groundwater
or salinity values from the Parquet file or from demo features.

## Endpoints

### `GET /maps/layers`

Returns a JSON array of map-layer metadata:

```json
[
  {
    "id": "current-salinity",
    "label": "Current Salinity",
    "available": false,
    "tileUrl": null,
    "dataUrl": null,
    "unit": null,
    "legend": [],
    "attribution": null,
    "status": "data_pending"
  }
]
```

`tileUrl` stays `null` because this backend does not currently run a raster
tile service. A production layer's `dataUrl` points at the existing JSON-grid
endpoint `/api/v1/maps/{scenario}/{period}?layer={variable}`. Legend entries
are supplied by the product's `legend` variable attribute as a JSON array of
`{ "label": string, "color"?: string, "minimum"?: number, "maximum"?: number }`;
no scientific ranges are invented by the API. Future salinity layers use IDs
`salinity-{ssp245|ssp585}-{2030|2050|2080}`.

### `GET /predictions/location`

Query parameters:

| Name | Type | Requirement |
| --- | --- | --- |
| `latitude` | number | Required; -90 through 90 |
| `longitude` | number | Required; -180 through 180 |
| `period` | `current`, `2030`, `2050`, `2080` | Optional; defaults to `current` |
| `scenario` | `current`, `ssp245`, `ssp585` | Optional; defaults to `current` |

`current` must be paired with `current`; future periods must be paired with
`ssp245` or `ssp585`. Example pending response:

```json
{
  "latitude": 26.85,
  "longitude": 80.95,
  "levelM": null,
  "salinityEcUsCm": null,
  "salinityProbability": null,
  "salinityRisk": null,
  "uncertainty": null,
  "applicabilityScore": null,
  "dataYear": null,
  "modelVersion": null,
  "status": "data_pending",
  "period": "current",
  "scenario": "current"
}
```

Prediction values are emitted only from a non-demo NetCDF product with a
`salinity_mean` variable, recognized conductivity units (`µS/cm` or equivalent),
`model_version`, and `data_year` metadata. Optional groundwater level,
probability, risk, uncertainty, and applicability fields are populated only
when their corresponding product variables and metadata exist.

### `GET /projections/location`

Uses the same query parameters and response schema as
`/predictions/location`, but requires `period=2030|2050|2080` and
`scenario=ssp245|ssp585`. Missing future data returns `data_pending`; no future
values are generated by the API.

### `GET /predictions/explanation`

Required query parameters: `latitude` (-90..90) and `longitude` (-180..180).
Returns `{ "latitude", "longitude", "features", "modelVersion", "status" }`.
Each feature has `name`, numeric `contribution`, and `direction`. Until a
validated prediction and compatible explanation artifact are available,
`features` is empty and `status` is `data_pending`.

### `POST /assistant/query`

Request JSON:

```json
{
  "message": "What is the salinity here?",
  "latitude": 26.85,
  "longitude": 80.95,
  "locationLabel": "Lucknow",
  "selectedLayer": "current-salinity",
  "period": "current",
  "scenario": "current"
}
```

`message` is required (1..4000 characters). Coordinates are optional but must
be supplied together. `selectedLayer` must be a layer ID returned by
`/maps/layers`. The response is `{ "answer": string, "actions": [], "status":
string }`. Without validated model output, the answer is
`I don't have a validated prediction for this location yet.` No AI service is
configured in this repository; the endpoint only returns an answer directly
from a validated backend prediction when one is available.

## Errors

FastAPI returns JSON `{ "detail": ... }` errors:

| HTTP | Meaning |
| --- | --- |
| `400` | Malformed request |
| `404` | Requested location/value is absent from an available product |
| `422` | Invalid coordinates, period, scenario, layer, or request body |
| `500` | Product could not be read or its metadata is malformed |
| `503` | An existing legacy product is missing required serving layers |

Pydantic/FastAPI parameter and body validation errors use `422`. A missing
scientific dataset is not an HTTP error: prediction responses use the documented
`data_pending` status so clients can render the unavailable state.

## Configuration

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `DATA_PATH` | `Backend/data/processed/master_observations.parquet` | Expected validated observation dataset |
| `MODEL_PATH` | `Backend/models/production` | Production model artifact location |
| `CMIP6_DATA_PATH` | `Backend/data/cmip6` | CMIP6 inputs |
| `AQUASHIELD_PRODUCT_DIR` | `Backend/data/processed` | Standardized NetCDF products served by current map/location APIs |
| `API_HOST` | `127.0.0.1` | Host used when running `python main.py` |
| `API_PORT` | `8000` | Port used when running `python main.py` |

`GET /health` reports whether the configured observation file, model path, and
CMIP6 path exist. Presence alone does not mark data as validated or make a
prediction available.
